# Code Review Fix instructions

Check commands come only from `.agents/adlc/REPO_CHECKS.md`. It names no runnable check today, so a fix
cannot be verified locally: say so in the report for every fix, and keep each fix to the lines the finding
covers.

## Convention pointers

The canonical examples to copy (`docs/conventions.md` has the full tables and the Patterns Library):

- **Template output:** `$escaper = $escaper ?? $block;`, then `escapeHtmlAttr` for attributes, `escapeUrl` for
  URLs, `escapeHtml` for text. See `view/frontend/templates/widget_div.phtml`.
- **Early return in templates:** `if (!($block->isEnabled() && $block->isRender...())) { return; }`. See
  `view/frontend/templates/reviews_tab.phtml:9-11`.
- **Config:** add the key to `$reviewsConfig` and a typed getter in `Model/Config.php`; never read
  `ScopeConfigInterface` from a block or template.
- **Yotpo API calls:** through `Model/Sync/Main::sync`, inside `try/catch (\Exception $e)` that logs with
  `$this->logger->info(__('API Issue - %1', $e->getMessage()))` and returns a default. See
  `Model/Sync/RichSnippets.php:97-137`.
- **Dependencies:** constructor injection; never add `ObjectManager::getInstance()`.
- **Types:** nullable defaults use `?Type $x = null` (commit `a59dba9`).

## Stack specifics

- **Magento module, no local runtime.** Nothing here compiles or runs outside a Magento installation, and
  no Magento installation is available in the fix loop. Do not add a `composer.lock`, `vendor/`, a
  `phpcs.xml` or any tool config as part of a fix.
- **Marketplace phpcs runs with `--ignore-annotations`.** Never fix a finding by adding `phpcs:ignore`,
  `phpcs:disable` or `@codingStandardsIgnoreLine`; they have no effect there.
- **One class per file.** A new enum or constants class goes in its own file (`Block/WidgetsLocations.php`,
  `Model/StarRatingSectionId.php`).
- **Generated classes.** `*Factory` classes are generated by Magento; reference them, never create them.
- **MFTF.** A test that saves Yotpo credentials goes under `Test/Mftf/Test/RequiresYotpoAccount/`
  (ADR-0001). MFTF never runs in the fix loop; say so in the report.

## Protected paths

`.claude/protected-files.json` is the source of truth. For this repo in particular:

- **Never write** (human-required): `composer.json`, `registration.php`, `etc/module.xml`,
  `etc/db_schema.xml`, `etc/db_schema_whitelist.json`, `etc/acl.xml`, `etc/csp_whitelist.xml`,
  `etc/config.xml`, `LICENSE.txt`, `LICENSE_AFL.txt`, `.github/workflows/**`, `.agents/adlc/**`,
  `.claude/**`, `CODEOWNERS`. A finding that needs one of these (a version bump, a schema column, an ACL
  resource, a CSP host, a new default) is out of scope. Report it; don't work around it.
- **Review-required:** all PHP under `Block/`, `Controller/`, `Helper/`, `Model/`, `Plugin/`, the rest of
  `etc/`, `view/**`, `Test/Mftf/Suite/**`, `CLAUDE.md`, `AGENTS.md`.
- **Public contracts:** never rename a config path, template, layout block name or public method of
  `Helper/Data.php` / `Block/Yotpo.php` to satisfy a finding; merchant themes use them.
- **Credentials:** never add a Yotpo app key, secret or token to any file.

## On-demand CI run

There is none. The repository has no CI workflow, so there is no `ci-on-demand.yaml` and no
`ready-for-merge-ci.yaml`. Do not create one as part of a fix.
